## 9月8日: [Gitコミットメッセージの書き方]
**■ 学習した内容・わかったこと**
* fix（バグ修正）、add（新規追加）、update（機能修正）、remove（削除）などの種別を先頭につけることで、変更の目的がひと目で分かりやすくなることを知りました。
* 複数の修正をひとまとめにするのはNGであり、できる限り細かい粒度（ひとつの変更ごとに独立させるなど）で行うのが望ましいという基準を学びました。

**■ コミット例**

3行目以降（詳細）:取得したAPIのプロパティ名が間違っていたため、userNameからnameへ修正しました。

1行目要約: [add] ルートアクセス時のリダイレクト処理を追加

3行目以降（詳細）: アプリ起動時にユーザーを自動的に /fridge ページへ誘導するため、app/page.tsx に redirect 処理を実装しました。

1行目要約: [update] ログインボタンのデザインと文言を変更

3行目以降（詳細）: ユーザービリティ向上のため、ボタンの色を青から緑に変更し、テキストを「ログイン」から「アカウントへログイン」に変更しました。

## 9月8日: [filter メソッド]
**■ 内容**
* Reactの useState を使った一覧画面で削除ボタンを押すと、押していないデータまで消えたり、リロードすると表示がコロコロ変わったりする不安定な挙動が起きました。
* StockList.tsx 内の filter メソッドの条件式で、stock.id == id と記述してしまっていたことが原因でした。
* JavaScriptの filter は「条件に当てはまるもの（True）だけを『残す』」という仕組み。
今回 == にしてしまったことで、「削除したいデータだけを残し、それ以外を全部消す」という意図と真逆の処理になっていました。
